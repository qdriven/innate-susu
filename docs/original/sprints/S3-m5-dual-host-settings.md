# Sprint 3 — M5：双向宿主模型设置

> 来源：[plans/innate-dogic-dsh/05-stage-5-dual-host-settings.md](../plans/innate-dogic-dsh/05-stage-5-dual-host-settings.md)。
> 目标：simple 用户在 dogic 或 DSH Harness 内都能完成"模型来源 → 默认模型 → 接入"，背后由 magpie 负责。dev 保留完整 magpie 控制台不重写。
> 预估：3–4 天。前置：S2（M4）完成。
> 用户只接触两个概念：**模型来源**（订阅/API 来源、测试连接、已配置列表）与**默认模型**（可选模型、接入状态、保存并接入）。不暴露 provider 池/路由组/patch/协议互译。

```text
model-settings：schema、纯 UI、校验、应用计划与共享场景
   ├─ dogic adapter → plugin-model-gateway / 受限 IPC
   └─ DSH adapter   → dsh-workbench 的受限设置服务

两侧 adapter → MagpieCli → magpie → DSH 接线
```

---

## T5.1 设置 schema 与应用服务

- **做什么**：定义版本化 `ModelSettingsConfig`（provider 引用、默认模型、目标 Agent；**不含 key**）；`apply` 幂等，按步骤返回 `{step, ok, detail}`，失败停止后续动作并给恢复方式；MagpieCli 依赖注入，mock 覆盖空配置、重复应用、失败与免 key 订阅。
- **功能**：M3 旧计划中的"facade 极简配置"在 v2.0 的归宿——设置逻辑先做成宿主无关的应用服务，两侧 UI 只是薄适配；apply 的步骤化返回是"配置失败不得谎称部分成功"的基础。
- **如何验证**：schema 有版本字段与兼容读取测试；apply 幂等（重复调用结果一致）；失败停在当前步且 detail 可操作；真实二进制测试只读或隔离临时 `DSH_HOME`（硬约束 6）。
- **预估 / 依赖**：0.5–1 天 / S2。

## T5.2 dogic simple 原生设置页

- **做什么**：simple 模式"设置"页实现模型来源与默认模型两区块（替换当前"内嵌控制台简化入口"）；所有操作有进行中态与下一步错误提示；成功后状态灯实时更新、新 DSH 会话读新接线；dev 控制台、浏览器逃生口、断开恢复继续可用；设置操作日志只含时间/动作/结果（无 key、token、完整认证 URL）。
- **功能**：小白"≤3 步"指标的直接载体；同时消灭 simple 模式对 magpie 控制台嵌页的依赖。
- **如何验证**：干净环境走查：安装→选 simple→设来源→选模型→接入→对话真实回复，全程 ≤3 步、不离开 App、无第二应用、无手工配置；`evidence/m5/` 截图 + 走查录像；日志文件 grep 无 key/token。
- **预估 / 依赖**：1 天 / T5.1。

## T5.3 DSH 内设置贡献

- **做什么**：扩展 `plugins/dsh-workbench`，经 M4 已验证的真实 settings/panel 贡献点提供同一功能；不引入任意进程执行接口；simple/dev 可见性与 dogic 语义一致，无法确定模式时默认展示最少配置面；卸载后 DSH 原生设置恢复、无失效贡献点。
- **功能**：模型设置成为第二个双宿主能力；验证 M4 建立的贡献点机制可承载表单类交互。
- **如何验证**：真实 DSH 内完成来源→模型→接入→对话（同 T5.2 场景）；卸载插件后 DSH 原生设置页完好；双宿主术语与错误文案一致（对照场景清单）。
- **预估 / 依赖**：0.5–1 天 / T5.2。

## T5.4 降级与恢复

- **做什么**：magpie 缺失或网关失败给明确提示与安装/重试入口；直连模式只在能安全写 DSH 配置时开放并注明无故障转移/用量能力；`magpie dsh default` 恢复路径保留；配置失败不谎称部分成功；无 DSH、无 magpie、无模型、无效 key 四类场景双宿主测试。
- **功能**：工程规范回滚表要求"恢复与降级路径明确"；降级体验决定小白在异常路径上是否卡死。
- **如何验证**：四类缺失场景各有专项用例（双宿主）；恢复路径实测从失败状态回到可对话；UI 在每个失败分支有下一步动作。
- **预估 / 依赖**：0.5 天 / T5.2、T5.3。

## T5.5 双宿主 UAT 与文档

- **做什么**：按工程规范第 6 节在干净环境分别执行 dogic simple 与 DSH 宿主设置流程（UAT 6.1 / 6.2 脚本）；更新 module-map、build-path、方案网站与 `evidence/m5/`。
- **功能**：M5 出口标准的验收形式；UAT 脚本从此成为可重复资产。
- **如何验证**：UAT 通过标准逐条满足（≤3 步、无第二个应用、无手工配置、无高级术语弹错 + 无 magpie/无 DSH/无效 key 变体）；文档四处同步完成。
- **预估 / 依赖**：0.5 天 / T5.4。

## 出口标准（M5）

- dogic 与真实 DSH 内均可完成来源、模型、接线和恢复。
- dogic simple 从安装到首次对话 ≤3 步，全程不需要第二个应用或手工编辑配置。
- 双宿主安全约束、核心术语、错误行为一致；dev 高级能力零回退。
- 全量门禁、桌面冒烟与 DSH 宿主 E2E 通过；key/token 零泄漏。
