# Canvas 发布流程

1. 确认用户给出目标 Canvas；只操作该画布。未指定时，本次只交付 HTML 和快照。
2. 调用 `canvas` 与 `widget` 技能并读取目标 placements，保留无关小组件和布局状态。
3. 使用同一次 `sync` 的 `project-snapshot.json`。Sprint 和模块视图共享任务、模块及摘要数据。
4. 更新已有小组件时保留其身份；不要为修复数据而删除并重建整个画布。
5. 对每个更新的小组件执行 Widget 校验，再回读 Canvas 确认 mount、尺寸和顺序。
6. 检查真实渲染。至少确认任务数、下一任务、当前/目标图例、长文本和审计错误一致。
7. 报告快照哈希、审计结果和更新的小组件。预览模式产生的错误快照不得宣称发布验收通过。

CLI 不直接调用 Blueprint 工具，也不保存 Canvas ID。这样可避免测试或普通网站同步意外修改用户画布。
